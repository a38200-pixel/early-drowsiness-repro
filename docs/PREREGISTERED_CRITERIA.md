# 사전 기준 정리

## 1. 한 줄 요약

사전 기준은 결과를 보기 전에 문서에 적어 커밋해 둔 합격 조건이고(활용 트랙, 코드 폴더 improve의 기준만 다루며 재현 트랙의 사전 등록은 [REPRODUCTION_LOG.md](REPRODUCTION_LOG.md)에 있음), 그 뒤에 정해지거나 바뀐 것은 "사후 기준" 절에 있습니다. 결과를 본 뒤 바뀐 것은 2건(허용 오차 완화 1건, 사전 기준을 충족하지 못한 채 정한 임계값 0.15 1건)입니다. 내용은 기존 기록의 문장과 git 커밋 시각을 옮긴 것이며 새로 해석하거나 추측한 것은 없고, 용어는 [REPRODUCTION_RESULTS.md](REPRODUCTION_RESULTS.md)의 용어 표를 따릅니다.

## 2. 사전 기준

"순서 확인됨"은 기준을 적은 문서의 git 커밋 시각이 결과 기록의 커밋 시각과 산출물 수정 시각보다 앞선다는 것을 확인했다는 뜻이고, "순서 미확인"은 그것을 확인하지 못했다는 뜻입니다. 아주 작은 오차는 0.00001처럼 풀어 썼습니다.

1. **규칙 알람 실험 E-01** ([PREREG_E-01.md](improvement/PREREG_E-01.md)): 데모 영상 한 개(운전자 4명을 이어 붙인 편집본)에서 사람이 확인한 구간 3개(사건 1, 2, 3건, 합 6)마다 시작 2.0초 뒤부터 끝 1.0초 뒤까지를 창으로 잡고 그 안에 규칙 알람이 몇 건 드는지 세며(허용 오차 1.0초), 주 조건(임계값 0.21, 얼굴이 검출된 프레임만 쓰는 detected)에서 5건에서 6건이면 대부분 일치, 3건에서 4건이면 부분 일치, 0건에서 2건이면 불일치로 보고 임계값 3개와 유효 출처 2개의 6개 조합을 모두 보고합니다. 결과: 주 조건 일치 2건으로 불일치(규칙 정의 재검토), 사전 예측 3개 중 1개 일치이고 해석 구간, 창, 조합은 바뀌지 않았으며 작업 트리 상태 같은 실행 조건 일탈은 있었지만 기준 변경은 아닙니다. (순서 확인됨)
2. **규칙 알람 실험 E-02** ([PREREG_E-02.md](improvement/PREREG_E-02.md)): 대본 영상 한 개(정답 시각은 작성자가 규칙 실행 전에 기입)에서 눈 감기 사건마다 시작 2.0초 뒤부터 끝 1.0초 뒤까지를 창으로 잡고, 길이 3.5초 이상인 양성 사건은 창 안 알람이 1개 이상이면 일치로 보며, 1차 조건(임계값 0.21, detected만)에서 양성 3건 모두 일치면 일치, 2건이면 부분 일치, 1건 이하면 불일치이고 6개 조합과 사전 예측 5개, 정상 영상 대조도 정해 두었습니다. 결과: 양성 3건 중 3건 일치로 이 영상에서 일치, 음성 창 알람은 6개 조합 모두 0, 사전 예측 5개 중 5개 일치이며 정의, 상수, 조합, 해석 구간, 예측은 바뀌지 않았고 첫 커밋 뒤 달라진 것은 "실행 기록" 칸 두 곳을 채운 것뿐입니다. 5. **원본 연결 방식의 깜빡임 행 대조**: 원본 코드를 고치지 않고 실행해 받은 깜빡임 행이 재학습 모델 B1의 blinks 파일 행과 소수 4자리 줄 단위로 일치해야 한다는 기준입니다(기록에는 "합격 기준(제안)"으로 적힘, 영상 32/10_2와 32/10_1). 결과: 일치(행 9 대 9와 36 대 36, 열별 최대 차이 0), 기록상 사후 변경 없음. (순서 확인됨)

## 3. 사후 기준

꼬리표별 개수: 결과를 본 뒤 2건, 결과를 본 뒤 값은 그대로 1건, 결과를 보기 전 3건.

1. [결과를 본 뒤] **Freq 열 허용 오차 완화**: 실데이터 동치 검증(사전 기준 8번)에서 허용 오차가 1e-5(0.00001, 작업 지시문의 값이며 커밋된 사전 기록은 없음)에서 5e-3(0.005, 시험 허용)으로 완화되었습니다. 지시한 허용을 통과하지 못했고(최대 차이 0.003), 입력의 빈도 값이 소수 4자리로 반올림되어 저장되어 있어 얼굴 검출 프레임 수를 되살릴 때 후보가 여럿이 되는 구간이 있으며 되살린 값으로 다시 계산하면 0.000000001 이내로 일치하고, 시험 파일의 첫 커밋(2026-10-12 20:19)에 이미 0.005가 들어 있었습니다.
2. [결과를 본 뒤] **데모 임계값 0.15 고정**: 사전에 정한 선택 기준(사전 기준 3번)을 어떤 후보도 충족하지 못했고 작성자가 0.16과 0.17은 쓰기 어렵다고 판단해 0.15로 고정하기로 정했습니다. 기준 문장은 고치지 않았고 기록에 "사전 기준에 대한 일탈"이라고 적혀 있으며, 1명, 환경 한 곳, 시도 5번이라 통계적 의미가 없고 이 값을 근거로 한 주장을 하려면 새 데이터가 필요하다고 적혀 있습니다(원문은 로그의 해당 항목에 있음).
3. [결과를 본 뒤, 값은 그대로] **열림과 감김 길이 정의의 명문화**(결정 I-17): 정의를 문서로 명문화한 것은 E-01 결과를 확인한 뒤였지만 값은 바뀌지 않았습니다. 기록에는 "코드는 E-01 실행 전부터 이 정의대로였고 결과를 보고 바꾸지 않았다"고 적혀 있습니다.
4. [결과를 보기 전] **E-01 기준 사건**: 개별 사건 6건의 시각에서 구간 3개와 구간별 사건 수로 바뀌었습니다. 개별 시각을 얻지 못했고 작성자가 구간별 사건 수를 확인했기 때문이며, 커밋 전 수정이고 E-01은 실행하기 전이었습니다.
5. [결과를 보기 전] **E-01 구간 창의 시작**: 구간 시작 1.0초 전에서 구간 시작 2.0초 뒤로 바뀌었습니다. 규칙은 3.0초 지속 뒤에 알람을 내므로 구간 안에서 시작한 감김의 알람은 구간 시작 3.0초 뒤보다 일찍 나올 수 없고 여기에 허용 오차 1.0초를 적용했으며, 커밋 전 수정입니다.
6. [결과를 보기 전] **E-02 구간 표**: 구간 C 끝 67초와 구간 D 끝 86초가 68초와 87초로 바뀌었습니다. 정답 기록(DATA_REGISTRY)이 바뀌어 맞춘 것이며 커밋 전 수정입니다.

"커밋 전 수정"은 문서의 변경 이력과 로그가 그렇게 적은 것이며, 문서의 첫 커밋에는 최종본만 들어 있어 중간 판은 git으로 확인할 수 없습니다. 시험 코드의 기대값 조정은 기록에서 기준 변경으로 다루지 않았으면 넣지 않았습니다.

## 4. 사전 기준이 없는 것

1. 웹캠 실행(4회)의 처리 속도, 첫 점수가 나온 시각, 알람 대응(의도한 알람 시각은 기억 기반의 근사)에 대해 합격 기준을 정한 기록을 찾지 못했고, 값은 관찰로만 기록되어 있습니다.
2. 데모 임계값 후보 0.15, 0.16, 0.17을 고른 것은 작성자의 웹캠 체험 판단이며 측정이 아니라고 기록되어 있고(결정 I-21), 선택 기준은 그 뒤에 만들어졌습니다(사전 기준 3번).
3. E-02의 영상 1이 "3초 이상 감김 없음"이라는 것은 작성자 진술이며 기록상 확인하지 않았습니다.
4. 3.0초 알람 기준은 사전 고정된 규칙 값이고(결정 I-03, 결정 I-05), 실험에서 이 값의 위치를 시험하지 못했다고 기록되어 있습니다(E-02, 양성 사건이 모두 6초에서 7초 길이).
