## 바꾼 이유와 기준

- 앞 항목에서 기준 사건 6건의 개별 시각을 재현 로그에서 얻지 못했고, 사용자 표도 전달되지 않았다. 대신 사용자가 **구간별 사건 수**를 확인했다(2026-10-06): 0:12~0:19 = 1건, 0:45~1:05 = 2건, 1:09~1:22 = 3건, 합 6. 이 건수는 SVM 기록에서 도출했고 사용자가 2026-10-05에 육안으로 본 것과 같다고 확인했다. 규칙 가지의 결과와 무관하다. [확실] (사용자 확인)

- 새 파일: `ear_dump.py`(`format_row`, `DumpWriter`), `blink_video_dump.py`(복제본), `tests/test_c1b.py`. 앞 단계의 `tests/test_session_log.py`는 패키지 소스에서 `cv2`와 `PIL`을 금지하던 검사를 추출기 복제본에 한해 허용하도록 고쳤다(저장 관련 토큰 `imwrite`, `imsave`, `VideoWriter` 등은 모든 파일에서 그대로 금지). [확실]
- 복제본은 원본 583줄이 604줄이 되었다. 변경 표시 블록은 19개(CLI 4, GUI-REMOVED 9, DUMP 6)이고 인접한 블록이 합쳐져 연속 변경 구간은 17개이다. 복제본에만 있는 줄은 57줄, 원본에만 있는 줄은 36줄(빈 줄 3줄 포함)이다. [확실]
- 덤프 행: 프레임을 읽은 직후 `dump_index`(0부터, 읽은 모든 프레임)를 매기고 프레임마다 한 행을 쓴다. 얼굴 검출 분기에서 EAR을 계산한 프레임은 `detected`, 광학 흐름 추적에 성공해 EAR을 갱신한 프레임은 `tracked`, 그 밖에 EAR이 갱신되지 않은 프레임은 `none`(EAR 칸 비움)이다. 시각 = `dump_index / fps`(소수 6자리)이고 fps는 `CAP_PROP_FPS`에서 시작할 때 한 번 읽는다. [확실]

## 문서가 정하지 않아 제안으로 둔 지점과 승인 대기

- 출력 파일 이름 `blinks.txt`와 `ear_dump.csv`, `--out-dir`에 이미 같은 이름의 파일이 있으면 이어 쓰지 않고 종료하는 동작, 실행 방법(`python -m improve.rules.blink_video_dump`, 상대 가져오기 때문에 모듈로 실행). [확실] (제안)
- 덤프 시간축은 읽은 모든 프레임 기준이고, 저자 blink 기록의 시간축(얼굴 검출 프레임만 셈)과 다르다. 두 시간축의 대응은 실행 뒤 확인한다(I-16, 사용자 승인 대기). [확실]
- [D1_REQUIREMENTS.md](D1_REQUIREMENTS.md) C1과 C2의 입력 서술(타임스탬프, EAR 평균, 얼굴 검출 여부)은 C1b와 `replay.py`가 쓰는 형식(`timestamp_s, ear_left, ear_right, source`)과 다르다. C1b 절과 RULE_SPEC 7.1절은 후자와 같다. C1과 C2의 서술은 이번에 고치지 않았다(제안: 후자로 정정). [확실]
- 결정 [I-16](DECISIONS.md)은 사용자 승인 대기이다. [확실]
