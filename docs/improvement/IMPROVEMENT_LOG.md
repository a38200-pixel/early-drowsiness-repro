- 앞 항목에서 기준 사건 6건의 개별 시각을 재현 로그에서 얻지 못했고, 사용자 표도 전달되지 않았다. 대신 사용자가 **구간별 사건 수**를 확인했다(2026-10-06): 0:12~0:19 = 1건, 0:45~1:05 = 2건, 1:09~1:22 = 3건, 합 6. 이 건수는 SVM 기록에서 도출했고 사용자가 2026-10-05에 육안으로 본 것과 같다고 확인했다. 규칙 가지의 결과와 무관하다. [확실] (사용자 확인)

- 기존 정의(`src/repro/orientation_common.py`): 방향 이름 "0", "cw90"(시계 방향 90도), "180", "ccw90"(반시계 방향 90도). `rotate_frame`은 `cv2.rotate`에 `ROTATE_90_CLOCKWISE`, `ROTATE_180`, `ROTATE_90_COUNTERCLOCKWISE`를 넘긴다. `reproduction_blink_headless.py`의 `--rotate none|cw90|ccw90|180`은 `frame = imutils.resize(frame, width=450)` 한 곳을 `imutils.resize(cv2.rotate(frame, ...), width=450)`로 치환해 원본 프레임을 먼저 회전한 뒤 같은 리사이즈를 한다(`build_replacements`의 107~109행). `survey_orientation.py`도 같은 `rotate_frame`으로 방향 4가지의 얼굴 수를 센다(`count_by_orientation`). 기존 방향은 영상의 회전 태그를 읽은 값이 아니라 사용자가 지정하는 값이다. - 대조 결과: `apply_rotation(frame, 90)`은 기존 cw90과, 270은 ccw90과, 180은 180과 같은 화소 변환이다. 합성 비대칭 배열(2×3, 4×6×3 uint8)에서 모든 화소와 shape가 같았고, 기존 함수의 결과도 손계산 기대값과 같았다(두 구현이 같은 방향으로 틀리지 않았음). 기존 함수는 import해서 호출만 했으며 수정하지 않았다. 시험 3개를 `tests/test_video_rotation.py`에 추가했다(`ExistingRotationAgreementTest`). 불일치는 없었다. [확실] (측정)
- 이름 체계의 차이(사실): 새 구현은 시계 방향 각도(90, 180, 270)이고 기존은 cw90, 180, ccw90이다. 같은 변환의 대응은 90 = cw90, 270 = ccw90, 180 = 180이다. 회전 후 리사이즈하는 순서는 같다. [확실]
- 전체 단위시험: 208개 통과(205 + 3), 실패 0, 건너뜀 0. [확실]
