# D1 구현 요구사항 (C1~C5)

작성일: 2026-10-06. 규칙 가지와 데모 GUI의 첫 구현(D1) 단계별 요구사항이다. **코드는 쓰지 않았다.** 규칙은 [RULE_SPEC.md](RULE_SPEC.md), 결정은 [DECISIONS.md](DECISIONS.md), 기준 출력은 [BASELINE_OUTPUTS.md](BASELINE_OUTPUTS.md)에 있다. 확실도는 [확실], [가능성 높음], [추측]이고 확인하지 않은 것은 "미검증"으로 쓴다. 상태 단어는 "일치/불일치/미확정/미검증"만 쓴다. "제안"은 결정이 아니다.

## 공통 원칙

- 파이프라인과 탐지기를 조정하지 않는다. EAR 추출은 저자 코드의 정의를 따른다(RULE_SPEC.md 3절). [확실] (재현 충실성 원칙)
- 모든 시험은 **합성 데이터**만 쓴다(아래 시험 목록). 실제 영상으로 하는 확인은 시험이 아니라 별도 점검이며 사전 등록 대상이다. 단 C5의 기준 출력 대조는 B1 시퀀스와 체크포인트를 읽는 통합 점검이다(C5 참고). [확실]
- 영상, 프레임, 이미지를 저장하지 않는다. 사용자 이름, 절대경로, 이메일을 추적 파일에 쓰지 않는다. [확실] (방침)
- 80 epoch 학습은 에이전트가 실행하지 않는다. 패키지를 설치하지 않는다(I-12). [확실]
- 환경: Python 3.6 / TF 1.8.0 환경(`ghoddoosian_tf1`) 안에서 구현한다(I-12). 이번 점검에서 `tkinter`(tk ok), `PIL`(Pillow 8.3.1), `cv2`(3.4.5)의 import가 가능했다. [확실] (import 확인) `PIL.ImageTk`의 사용 가능 여부와 웹캠 접근 가능 여부는 확인하지 않았다(미검증).

## C1 EAR 추출기

| 항목 | 요구사항 |
|---|---|
| 입력 | 영상 파일 경로 또는 웹캠 장치. 프레임 하나씩 |
| 출력 | 프레임마다 (타임스탬프(초), 양쪽 눈 EAR 평균, 얼굴 검출 여부). 영상·프레임은 저장하지 않음 |
| 정의 일치 | EAR 수식, 보정(C < 0.1이면 0.3, 0.45 제한), 양쪽 평균, 리사이즈 450, 그레이스케일, 감마 1.5, 첫 번째 얼굴만 사용이 `blink_video.py` 줄 번호(RULE_SPEC.md 3절)와 일치해야 한다 |
| 얼굴 미검출 프레임 | EAR 값 없음으로 출력한다(`detected = false`). 광학 흐름 추적을 쓸지는 미확정이다. 저자 코드는 쓰지만(486-523줄) 이 규칙 가지가 쓸지는 결정되지 않았다(I-W-11) |
| 타임스탬프 | 영상 모드와 웹캠 모드의 출처는 RULE_SPEC.md 2절의 제안을 따른다(미확정). 프레임 번호만으로 시간을 계산하지 않는다 |
| 일치 확인 | 합성 랜드마크(고정된 눈 좌표)로 EAR 수식의 값이 저자 수식과 같은지 본다. 같은 입력에서 값이 다르면 "불일치"로 기록한다 |

## C1b 영상 추출기 (구현 보류)

| 항목 | 요구사항 |
|---|---|
| 내용 | 저자 스크립트의 **복제본**(`src/improve/rules/` 안)에 프레임별 `(timestamp_s, ear_left, ear_right, source)` 덤프를 추가하는 영상 추출기. 저자 파일 자체는 수정하지 않는다 |
| 출처 열 | `source`는 `detected` / `tracked` / `none`이다(RULE_SPEC.md 7.1절). 코드에 출처 변수가 없으므로 복제본에서 분기마다 값을 기록한다 |
| 상태 | **이번 단계에서는 구현도 실행도 하지 않는다.** 영상이 준비된 뒤 별도 단계에서 한다. 그때 영상 파일 이름과 절대경로는 추적 파일에 쓰지 않고, 프레임과 이미지는 저장하지 않으며, 얼굴 검출기 설정과 파이프라인을 조정하지 않는다 |
| 출력 | CSV(열 `timestamp_s, ear_left, ear_right, source`). C2의 오프라인 재생이 읽는 형식이다. 출력 폴더는 필수 인자로 받는다 |

## C2 상태기계와 오프라인 재생

| 항목 | 요구사항 |
|---|---|
| 입력 | (타임스탬프, EAR 평균, 얼굴 검출 여부)의 시계열 |
| 상태기계 | RULE_SPEC.md 5절(I-05~I-07). 임계값(0.21)과 지속 시간 기준(3.0초)은 설정값으로 받되 기본값은 고정이다 |
| 알람 출력 | RULE_SPEC.md 6절의 필드 |
| 오프라인 재생 | 같은 EAR 시계열에 임계값 0.15 / 0.21 / 0.25를 바꿔 다시 돌려 알람 수와 구간 길이 분포를 낸다(I-10). 3.0초와 0.3초 기준은 이 재생에서 바꾸지 않는다. 실험 번호 E-01은 사전 등록에서 부여한다 |
| 시간 비교 | 3.0초와 0.3초 경계는 부동소수점 오차로 흔들리지 않게 비교해야 한다(예: 정수 프레임 번호와 fps에서 시간을 계산하거나 오차 허용을 정한다). 방식은 미확정이다 |
| 판정 불가 구간 | **판정 불가 구간의 시작·끝 시각과 길이, 구간 수를 재생 결과에 반드시 포함한다**(RULE_SPEC.md 7.1절). 입력의 출처 열(`detected` / `tracked` / `none`)에서 어느 출처를 유효 EAR로 볼지는 재생 때 선택하며 기본값은 미확정이다(I-15, I-W-14) |

### 합성 시험 목록 (코드 없이 기대 결과만 적음)

프레임 간격은 1/30초를 예로 든다(프레임 번호 ÷ 30). 기대 결과는 RULE_SPEC.md의 제안 해석(구간당 한 번 알람, 3.0초에 도달한 프레임에서 알람, 열린 간격도 구간 시간에 포함)에 따른다. 제안 해석이 바뀌면 기대 결과도 바꾼다(I-W-11).

| 번호 | 입력(합성) | 기대 결과 |
|---|---|---|
| S-01 | EAR 0.30 일정, 10초 | 알람 없음, 구간 없음 |
| S-02 | EAR 0.10 일정, 10초 | 알람 1회(시작 후 3.0초에 도달한 프레임), 구간은 영상 끝까지 |
| S-03 | EAR 0.10으로 89프레임(2.9667초) 후 0.30 | 알람 없음(3.0초 직전). 구간은 열림 0.3초가 지나면 해제 |
| S-04 | EAR 0.10으로 90프레임(3.0초) 후 0.30 | 알람 1회(3.0초 포함, "이상"). 경계 포함 여부는 I-05 문구를 따른다 |
| S-05 | EAR = 0.21 정확히 일정 | 닫힘(≤ 0.21 포함)으로 처리되어 S-02와 같은 결과 |
| S-06 | 닫힘 60프레임, 열림 8프레임(0.2667초), 닫힘 60프레임 | 열림이 0.3초 미만이므로 해제되지 않고 하나의 구간이 이어짐. 시작 후 3.0초에 도달하면 알람 1회(열린 간격도 구간 시간에 포함, 제안) |
| S-07 | 닫힘 60프레임, 열림 9프레임(0.3초), 닫힘 60프레임 | 열림이 0.3초이므로 해제되어 구간이 둘로 나뉜다. 각 구간 길이가 2.0초라 3.0초 미만이므로 알람 없음 |
| S-08 | 닫힘 60프레임 중 얼굴 미검출 27프레임(0.9초) | 1초 미만이므로 직전 상태 유지, 구간 계속 |
| S-09 | 닫힘 60프레임 중 얼굴 미검출 30프레임(1.0초) | 1초 이상이므로 "판정 불가", 구간 폐기. 이미 울린 알람은 유지 |
| S-10 | 알람이 울린 뒤 얼굴 미검출 30프레임 | 알람은 취소되지 않음. 판정 불가 상태 기록 |
| S-11 | 프레임 간격이 불규칙한 타임스탬프(예: 1/30초와 1/15초 혼합)로 닫힘 | 프레임 수가 아니라 타임스탬프 차이로 지속 시간을 계산 |
| S-12 | 닫힘 상태에서 영상이 끝남(진행 중 구간) | 제안: 구간 끝 = 영상 끝 시각으로 기록(I-W-11) |
| S-13 | 같은 시계열에 임계값 0.15 / 0.21 / 0.25를 적용(예: EAR이 0.18 일정) | 0.15에서는 열림, 0.21과 0.25에서는 닫힘이어서 알람 수가 달라짐 |

## C3 로그와 메모 저장

| 항목 | 요구사항 |
|---|---|
| 판정 로그 파일 형식(제안, 미확정) | 텍스트 한 줄에 한 사건(CSV). 열: 타임스탬프(초), 양쪽 EAR 평균, 얼굴 검출 여부, 상태, 알람 여부, 임계값. 영상 이름은 쓰지 않고 실행 식별자만 쓴다 |
| 메모 파일(제안, 미확정) | 타임스탬프(초)와 사용자가 쓴 짧은 텍스트. 별도 파일. 알람을 보기 전에 메모를 먼저 기록할지는 미확정이다(I-W-09) |
| 개인정보 | 사용자 이름, 절대경로, 이메일, 영상 파일 이름을 로그와 메모에 쓰지 않는다. 데모 영상에 얼굴이 있으므로 영상, 프레임, 이미지를 저장하지 않는다 |
| 저장 위치(제안) | 저장소 밖 폴더(경로는 환경변수로 받음). 로그와 메모는 추적 파일에 커밋하지 않는다. 결과를 요약해 기록할 때만 `IMPROVEMENT_LOG.md`에 숫자로 옮긴다 |
| 블라인드 여부 | 데모 영상은 블라인드가 아니다(사용자가 내용을 안다). 메모와 알람의 대조에는 기대 편향이 들어갈 수 있다(I-W-09, RULE_SPEC.md 8절) |

## C4 tkinter GUI

| 항목 | 요구사항 |
|---|---|
| 모드 | 웹캠 모드와 영상 파일 모드를 모두 지원한다(I-11) |
| 표시 | 현재 상태(열림/감김/판정 불가), 지속 시간, 알람, 유효성 경고("탐지 불가능", I-09), EAR 값. "신뢰 불가" 표시는 제안이며 미확정이다(I-W-12) |
| HM-LSTM 점수 | 표시할지는 미확정이다(I-W-08, 기본 제안은 포함하지 않음) |
| 입력 | 사용자의 판단 메모(C3). 메모와 알람의 순서는 미확정이다(I-W-09) |
| 프레임 | **저장하지 않는다.** 화면 표시용 메모리 사용에 한한다. 타임스탬프를 쓴다(프레임 수로 시간을 세지 않는다) |
| 환경 | `tkinter`는 import 가능(tk ok), Pillow 8.3.1은 import 가능, `PIL.ImageTk` 가능 여부는 미검증이다. 설치하지 않는다. 필요한 모듈이 없으면 `cv2`의 창 표시로 대체할지 사전에 정한다(미확정). 웹캠 접근 가능 여부는 미검증이다 |
| 한계 | 웹캠 모드에서는 프레임 간격이 일정하지 않을 수 있다. 처리 속도는 1920×1080 영상 단일 프로세스에서 실시간 배수 0.84로 측정된 적이 있다(재현 로그 "데모 점검 결과 (2026-10-05)", 한 영상). 다른 해상도와 웹캠에는 일반화하지 않는다 |

## C5 B1 래퍼와 기준 출력 대조 시험

| 항목 | 요구사항 |
|---|---|
| 인터페이스 | `score_sequences(array) -> scores` 형태로 고정한다(I-14). 입력은 blink 윈도우 배열(B1과 같은 입력 형식: 길이 30의 시퀀스, 특징 4개 순서 [Freq, Amp, Dur, Vel]), 출력은 시퀀스별 점수이다. 점수의 정확한 의미(회귀 출력, 클래스별 점수 등)는 B1이 낼 수 있는 것에 따라 정하며 미확정이다 |
| 정규화 | B1 학습·평가가 쓴 정규화(개인별 z-score, 학습 통계를 쓴 특징별 z-score)를 래퍼가 어떻게 다룰지는 미확정이다. 래퍼가 정규화를 하는지 입력이 이미 정규화된 상태인지 사전 등록 전에 정해야 한다 |
| 체크포인트 | 기존 B1 체크포인트를 읽기만 한다(수정 금지). 15개 체크포인트의 위치 규칙은 BASELINE_OUTPUTS.md 2.2절 |
| 합성 시험 | 래퍼의 입출력 형식 시험은 합성 배열만 쓴다: 올바른 shape의 합성 입력에서 점수 개수가 입력 개수와 같은지, 같은 입력에서 반복 호출 결과가 같은지, 잘못된 shape에서 명확한 오류를 내는지 |
| 기준 출력 대조 | 래퍼의 영상별 예측을 기준 출력(BASELINE_OUTPUTS.md 2.1절)과 비교한다. 이 비교는 합성 데이터가 아니라 B1 시퀀스와 체크포인트를 읽는 통합 점검이며, 사전 등록에서 허용 오차를 정한다. 결과는 "일치/불일치/미확정/미검증"으로 쓴다 |
| 학습 | 80 epoch 학습은 하지 않는다 |
