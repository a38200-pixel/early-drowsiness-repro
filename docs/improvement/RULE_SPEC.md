# 규칙 가지 명세 v1 (눈 감김 지속 알람)

작성일: 2026-10-06. 결정은 [DECISIONS.md](DECISIONS.md)의 I-04~I-14가 원본이고, 이 문서는 그 결정을 구현 가능한 형태로 풀어 쓴 명세이다. 구현은 아직 없다. 확실도는 [확실], [가능성 높음], [추측]이고 확인하지 않은 것은 "미검증", 논문에 명시되지 않은 수치는 "not explicitly reported"로 쓴다. 상태 단어는 "일치/불일치/미확정/미검증"만 쓴다. "제안"으로 표시한 것은 결정이 아니다.

## 1. 목적과 범위

- 눈 기반 신호만 다룬다. 하품과 고개 떨굼은 범위 밖이다(I-01). [확실]
- 구조: **빠른 규칙 가지**(프레임마다 눈 감김 지속 시간을 보고 알람)와 **느린 HM-LSTM 가지**(기존 B1 모델이 blink 시퀀스를 보고 점수를 냄)를 병렬로 둔다. 초기 결합은 단순 OR(둘 중 하나가 알람이면 알람)이다. 결합 방식의 개선은 이 문서의 범위 밖이다. [확실] (사용자 결정, 결합 OR는 초기값)
- 규칙 가지는 파이프라인과 탐지기(dlib 정면 검출기, 68 랜드마크)를 조정하지 않는다(재현 충실성 원칙). 규칙 가지가 쓰는 것은 EAR 값과 타임스탬프뿐이다. [확실] (방침)

## 2. 입력

- 영상 파일 또는 웹캠의 프레임과 **타임스탬프**(초). 프레임 수가 아니라 시간으로 판정한다(I-05). [확실]
- 영상 파일 모드의 타임스탬프 출처(제안, 미확정): 프레임 번호 ÷ 영상의 fps 또는 영상 컨테이너가 주는 위치 시간. 웹캠 모드(제안, 미확정): 단조 증가 시계로 프레임 도착 시각을 잰다. 어느 쪽이든 프레임 간격이 일정하다고 가정하지 않는다(I-W-15).
- 얼굴이 검출되지 않은 프레임은 EAR 값이 없는 프레임으로 다룬다(5절 상태기계 참고).

## 3. EAR 정의

EAR은 저자 코드(`third_party/ghoddoosian/blink_video.py`)의 정의를 그대로 따른다. 줄 번호는 이 파일 기준이다. [확실] (코드 읽기, 실행하지 않음)

| 항목 | 코드 사실 | 줄 |
|---|---|---|
| 눈 랜드마크 | `face_utils.FACIAL_LANDMARKS_IDXS`의 왼쪽 눈과 오른쪽 눈을 쓴다. imutils 0.5.4에서 확인한 값은 왼쪽 눈 (42, 48), 오른쪽 눈 (36, 42)이다 [확실] (이 환경에서 상수를 읽음) | 318-319, 415-416 |
| 수식 | A = dist(eye[1], eye[5]), B = dist(eye[2], eye[4]), C = dist(eye[0], eye[3]), EAR = (A + B) / (2.0 × C). `dist`는 scipy의 유클리드 거리 | 6, 77-78, 82, 88 |
| 보정 | C < 0.1이면 EAR = 0.3(광학 흐름의 수치 문제 대비). EAR > 0.45이면 0.45로 제한 | 84-85, 89-90 |
| 양쪽 눈 | 양쪽 눈 EAR의 평균을 쓴다(한쪽만 쓰지 않음) | 417-421 |
| 전처리 | 프레임 너비를 450으로 리사이즈(imutils), 그레이스케일, 감마 1.5 보정 | 359, 368, 370 (`adjust_gamma` 29-37) |
| 얼굴 검출 | dlib 정면 얼굴 검출기, 첫 번째 얼굴(`rects[0]`)만 사용 | 311, 378, 386 |
| 얼굴 미검출 프레임 | 광학 흐름(LK)으로 이전 눈 랜드마크를 추적해 12점이 모두 추적되면 EAR을 갱신한다. 추적되지 않으면 EAR 값이 갱신되지 않는다 | 486-523 (조건 497) |
| 13프레임 EAR 창과 SVM | `EAR_series`는 길이 13이고 프레임마다 한 칸 밀린다. SVM(`loaded_svm.predict`)이 이 창으로 닫힘 여부를 분류한다. 관심 프레임은 `EAR_series[6]`이다. 프레임 큐 `Q`의 크기는 7이다 | 330, 423, 444, 447, 48, 315 |
| EMERGENCY 카운터 | `ear < 0.21`이면 카운터 +1, 50 이상이면 문구를 **출력만** 하고 카운터를 0으로 되돌린다. `ear >= 0.21`이면 카운터를 0으로 되돌린다. EAR이 갱신되는 프레임에서만 호출된다(얼굴 검출 분기와 광학 흐름 분기 각 1곳) | 110-120, 435, 519 |
| 타임스탬프 | `ElapsedTime`을 계산하지만(373) 이 파일 안에서 다른 곳에 쓰이지 않는다. 판정은 프레임 수(`reference_frame` 369, `number_of_frames` 380)로 한다 | 349, 373 |

주의:

- **EAR은 사람 눈의 감김 비율이 아니다.** 랜드마크 비율이며 EAR 0.21이 눈이 79% 감겼다는 뜻이 아니다. 사람마다 열린 눈의 EAR 값이 다르다. [확실] (정의)
- I-04의 임계값 0.21은 저자 코드의 EMERGENCY 조건 `ear < 0.21`(110-111줄)과 같은 값이다. 이 값을 사용자가 고른 이유가 저자 코드에서 왔는지는 확인되지 않았다(미확인). [확실] (값의 일치만 확인)
- 저자의 EMERGENCY는 프레임 수 50(영상 fps에 따라 시간이 달라짐, 예를 들어 23.976 fps이면 약 2.09초)으로 세고 출력 외에 하는 일이 없다. 이 규칙 가지는 시간(3.0초)으로 센다는 점이 다르다. 또 저자의 EMERGENCY는 `ear < 0.21`(미만)이고 I-04는 `EAR ≤ 0.21`(이하)이라 경계값 0.21의 처리가 다르다. [확실] (코드 읽기와 산술)
- 저자 코드의 EMERGENCY는 EAR이 갱신되지 않은 프레임에서는 호출되지 않아 카운터가 그대로 유지된다. 이 명세의 상태기계(5절)와 다르다. [확실] (코드 읽기)

## 4. 닫힘 판정

- 한 프레임에서 **닫힘** = 양쪽 눈 EAR 평균 ≤ 0.21 (고정 임계값, I-04). **열림** = EAR 평균 > 0.21. [확실] (사용자 선택)
- 이동평균 등 평활화를 쓰지 않는다(I-08). 한 프레임의 값으로 판정한다. [확실] (사용자 선택)
- 사람별 보정은 쓰지 않는다. 유효성 검사(7절)가 보정이 필요한 상황을 경고로 알려 준다. [확실]
- SVM 닫힘 분류는 규칙 가지에 쓰지 않는다(EAR 임계값만 쓴다). SVM은 저자 blink 추출 파이프라인의 일부이며 이 규칙 가지와 별개이다. [확실] (사용자 결정, I-04)

## 5. 감김 구간 상태기계

시간은 모두 타임스탬프(초)이다. 상태: **열림**(구간 없음), **감김**(구간 진행 중), **판정 불가**(얼굴 미검출이 1초 이상 이어짐). 구간 시작 시각 `t_start`는 닫힘이 시작된 첫 프레임의 시각이다. [확실] (I-05~I-07). 표의 "확정" 표기는 2026-10-06 사용자 "제안대로"(I-W-11)로 확정한 것이다. 표와 문단에 남은 "제안"은 확정하지 않은 부분이다.

| 현재 상태 | 이벤트 | 다음 상태와 동작 |
|---|---|---|
| 열림 | 닫힘 프레임 | 감김으로 전환. `t_start` = 이 프레임 시각 |
| 감김 | 닫힘 프레임 | 감김 유지. 지속 시간 = 현재 시각 − `t_start`. 지속 시간 ≥ 3.0초이고 이 구간에서 아직 알람이 없으면 **알람 1회**(확정(사용자, 2026-10-06 "제안대로"): 구간당 한 번, 구간 길이가 3.0초에 도달한 시점의 첫 샘플에서) |
| 감김 | 열림 프레임 | "열림 연속 시간" 측정 시작(`t_open`). 열림이 연속 0.3초 이상이 되면 구간 해제(열림으로 전환). 구간 끝 시각 = `t_open`(확정(사용자, 2026-10-06 "제안대로") (사용자 확인, 2026-10-06): 열린 구간이 시작된 시각) |
| 감김, 열림 연속 0.3초 미만 | 다시 닫힘 | 열림 연속 측정을 취소하고 같은 구간을 계속한다(감김 유지). 열린 간격은 구간 시간에 포함한다(확정(사용자, 2026-10-06 "제안대로")) |
| 감김 또는 열림 | 얼굴 미검출 | 미검출 시작 시각을 기록한다. 1초 미만이면 직전 상태를 유지한다(확정(사용자, 2026-10-06 "제안대로") (사용자 확인, 2026-10-06): 미검출 동안에도 시간은 흐르고 지속 시간 계산에 포함됨) |
| 감김 또는 열림, 미검출 1초 이상 | 미검출이 계속 | **판정 불가**로 전환. 진행 중이던 감김 구간을 **폐기**한다. 이미 울린 알람은 취소하지 않는다 |
| 판정 불가 | 얼굴 검출 | 열림으로 전환(새 구간 판정 시작) |
| 감김 | 영상 끝 | 확정(사용자, 2026-10-06 "제안대로"): 진행 중인 구간이 3.0초 미만이면 폐기하고, 이미 울린 알람은 유지한다(확정, I-W-11 일부 해결). 구간이 3.0초 이상이면 알람이 이미 울렸으므로 구간을 유지하고 구간 끝을 확인된 마지막 시각으로 기록한다(이 마지막 부분은 제안) |

경계 조건(제안, 미확정, I-W-15. 여러 얼굴, 프레임 간격 불규칙, 경계 포함에 한정): 여러 얼굴이 검출되면 저자 코드처럼 첫 번째 얼굴만 쓴다(`rects[0]`, 386줄). 프레임 간격이 불규칙하면 타임스탬프 차이로 지속 시간을 계산한다. 3.0초 경계에서 "3.0초 이상"은 3.0초 정확히 포함이다. 0.3초 경계도 "0.3초 이상"은 포함이다. [확실] (I-05, I-06의 문구)

| 필드 | 내용 |

| 구간 시작 시각 | `t_start` |

| 임계값 | 알람 때 쓴 EAR 임계값(기본 0.21)과 지속 시간 기준(3.0초) |
| 신뢰 표시 | 유효성 검사(7절)가 경고 상태이면 "신뢰 불가"(표시 방식은 제안, I-W-12) |

영상, 프레임, 이미지는 저장하지 않는다. 로그에는 시각과 판정 값만 남긴다. [확실] (방침)

## 7. 유효성 검사

- 알림 기준 구간(클립 1)에서 **얼굴이 검출된 프레임만**의 EAR 중앙값이 0.21 이하이면 "탐지 불가능" 경고를 표시한다(I-09). 이 경우 EAR 임계값 0.21이 그 사람에게 맞지 않을 수 있기 때문이다. [확실] (사용자 결정) 이 경고가 맞는 판단인지는 검증하지 않았다(미검증).
- 경고 중에도 규칙은 계속 계산하고, 알람에 "신뢰 불가" 표시를 붙인다. 이 표시 부분은 제안이며 사용자가 확정하지 않았다(I-W-12). [확실]
- 기준 구간의 최소 길이는 미확정이다(제안 5분, I-W-10). 기준 구간을 어떻게 촬영할지도 미확정이다(I-W-13).
- **세션 전체 중앙값 방식은 쓰지 않는다**. 실제로 졸린 운전자의 알람을 가리기 때문이다(기각, I-09). [확실] (사용자 결정)

### 7.1 얼굴 없음의 정의와 출처 열 (I-15, I-W-14)

저자 코드의 얼굴 처리 사실(`third_party/ghoddoosian/blink_video.py`, 코드 읽기, 실행하지 않음). [확실]

| 사실 | 줄 |
|---|---|
| dlib 정면 검출기를 **매 프레임** 실행한다. N프레임마다 검출하는 조건과 간격 N은 없다 | 378 |
| 검출에 성공하면 랜드마크로 EAR을 계산해 EAR 창에 넣는다(검출 분기) | 379-423 |
| 검출에 실패한 프레임에서만 광학 흐름으로 이전 눈 점을 추적한다(첫 얼굴을 본 뒤, 눈 12점이 모두 추적될 때) | 486-497 |
| 추적에 성공하면 추적한 점으로 EAR을 계산해 EAR 창에 넣는다(추적 분기) | 503-507 |
| 추적에 실패하면 EAR 창은 갱신되지 않고 직전 값이 남는다(0으로 되돌리지 않음). 눈 점과 기준 프레임도 갱신되지 않아 다음 프레임에서 마지막 성공 프레임을 기준으로 다시 추적을 시도한다 | 491-497, 513-515 |
| 코드에 출처를 나타내는 변수는 없고, 분기(검출 379줄, 추적 497줄 `if` 안)로만 구분된다 | 379, 497 |

규칙 가지의 입력에는 프레임마다 **EAR 출처 열** `source`를 둔다(결정 I-15). 값은 다음 세 가지이다.

| source | 뜻 |
|---|---|
| `detected` | 검출 분기에서 계산한 EAR |
| `tracked` | 추적 분기에서 계산한 EAR |
| `none` | EAR이 갱신되지 않은 프레임(검출 실패, 추적 실패, 첫 얼굴 이전) |

- 규칙이 어느 출처를 유효 EAR로 볼지는 재생 때 선택한다. **제안 기본값(미확정, I-W-14)**: `detected`만 유효로 보고 `tracked`와 `none`은 "얼굴 없음"으로 취급한다. 이 기본값은 사용자가 확정하지 않았다.
- "얼굴 없음" 프레임의 처리는 5절의 상태기계(1초 미만이면 직전 상태 유지, 1초 이상이면 판정 불가)를 따른다.
- **판정 불가 구간 로그 필수**: 판정 불가 구간(시작·끝 시각, 길이)과 구간 수는 재생 결과와 로그에 반드시 포함한다. 판정 불가 구간이 알람 수와 구간 길이 분포 옆에 보이지 않으면 결과를 해석할 수 없다. [확실] (요구사항)

## 8. 민감도 분석 계획

- 임계값 0.15 / 0.21 / 0.25를 같은 영상에 **오프라인 재생**으로 비교한다(I-10). 영상에서 EAR 시계열(시각, EAR 평균, 얼굴 검출 여부)을 한 번 뽑아 두고, 임계값만 바꿔 상태기계를 다시 돌리는 방식이다(제안). EAR 추출은 파이프라인을 바꾸지 않는다. [확실] (결정과 방침)
- 보고할 지표: 임계값별 **알람 수**, **감김 구간 길이 분포**, 사용자 메모(영상을 보며 남긴 판단)와의 **대조**. 그 외의 지표는 사전 등록에서 정한다.
- 실험 번호 E-01은 사전 등록 단계에서 부여하고, 가설, 예측, 판정 기준은 `IMPROVEMENT_LOG.md`에 실행 전에 쓴다([../EVALUATION_PROTOCOL.md](../EVALUATION_PROTOCOL.md) 8절). 이 명세는 사전 등록이 아니다. [확실]
- 데모 영상은 블라인드가 아니다. 사용자가 영상 내용을 알고 있어 메모와의 대조에는 기대 편향이 들어갈 수 있다. 알람을 보기 전에 메모를 먼저 기록할지는 미확정이다(I-W-09). [확실]

## 9. 한계

- EAR과 눈 감김 비율은 같지 않고 사람마다 대응이 다르다. 0.21은 그 사람에게 맞는지 검증하지 않은 고정값이다. [확실]
- **3초와 0.21의 문헌 근거는 확인되지 않았다.** 부록 A의 문헌 중 3초 또는 0.21을 검증한 것은 없다. [확실] (확인한 범위에 한함)
- 3초는 마이크로슬립이 지속되는 범위(문헌에서 0.5–15초라고 하는 것, 부록 A) 안에 있지만, 그중 일부만 잡는다. 3초 미만의 마이크로슬립은 이 규칙으로 잡히지 않는다. [가능성 높음] (웹 요약 기반 문헌)
- 처리 속도: 1920×1080 영상을 단일 프로세스로 처리한 실시간 배수가 0.84였다(재현 로그 "데모 점검 결과 (2026-10-05)", 한 영상 측정, `conda run` 시작 시간 포함 상한). 한 영상 측정이므로 다른 영상과 환경에는 일반화하지 않는다. [확실] (한 영상에 한함)
- 얼굴 검출은 dlib 정면 검출기를 조정하지 않고 쓴다. 검출률이 낮은 영상(고개를 돌림, 어두움 등)에서는 판정 불가가 늘어난다. 검출률과 판정 불가 비율의 관계는 이 명세에서 측정하지 않았다(미검증).

## 10. B1 데이터와의 관계

- B1 영상 167개 중 3초 이상 blink가 있는 영상이 16개(9.6%)이다. 클래스별로는 클래스 0이 1/57, 클래스 5가 6/56, 클래스 10이 9/54이다. [확실] (재현 로그 "데모 점검 결과 (2026-10-05)"의 측정) 이 숫자는 blink 추출 파이프라인이 기록한 blink의 지속 시간(프레임 수)으로 센 것이고, 이 명세의 EAR ≤ 0.21 규칙으로 센 것이 아니다. 기록된 blink에 한정되며 두 방식이 같은 영상을 고르는지는 미검증이다.
- 규칙 가지는 B1 학습 데이터와 직접 연결되지 않는다. B1 모델(HM-LSTM)은 규칙 가지 옆에서 점수만 낸다. 래퍼 인터페이스는 I-14, 기준 출력은 [BASELINE_OUTPUTS.md](BASELINE_OUTPUTS.md)에 있다. [확실]
